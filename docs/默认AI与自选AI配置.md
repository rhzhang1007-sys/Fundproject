# 默认AI与自选AI配置

默认AI、网页自选AI和统一提示词已实现。本机现有默认模型配置保留；公开交付中的API模板留空。GitHub定时采集不再调用观点或新闻聚合模型，无需新填模型密钥。

## 站方配置一次，访客使用默认AI

1. 打开项目的 `prototype/.env.local`。如果尚未创建，可从 `.env.example` 复制。该文件不进入Git、交付ZIP或静态网页。
2. 私下填写以下三个值，不要把Key发到聊天或提交仓库：

```dotenv
WEB_LLM_API_URL=
WEB_LLM_API_KEY=
WEB_LLM_MODEL=
```

智增增可填写：地址 `https://api.zhizengzeng.com/v1/chat/completions`，模型 `glm-5.3-flash`；Key从自己的服务商后台复制。此前定时环境已实测Flash可用，不能据此保证任意账户或任意时刻都可用。

3. 确认 `WEB_LLM_DAILY_BUDGET`。模板为5元，可自行降低。已核对的智增增Flash价格自动取输入0.8、输出2.8元/百万token；`WEB_LLM_PRICE_IN`、`WEB_LLM_PRICE_OUT`可以一起留空。换其他服务商/模型时，两项都填写对应的人民币/百万token价格。价格表到2026-12-24须复核，过期不继续开放付费调用。
4. 在项目目录执行 `python3 prototype/serve.py`，或使用Node 22运行 `node prototype/web-ai-server.mjs`。当前端口被旧服务占用时，先在旧服务自己的终端按Control+C，再启动新服务。不要关闭WorkBuddy的持仓采集。
5. 打开终端显示的地址，进入“设置”，选择“默认 AI”并保存。服务配置有效时显示“默认 AI 可用”。摘要、核对和问答使用同一套产品提示；访客不需要自己的Key。

本机已准备官方Node 22运行环境，启动器会优先使用它。其他电脑请安装Node 22 LTS。`--static-only`只提供静态网页，不能运行默认AI服务。

服务端Key不回传浏览器。请求只接受任务、所选公开材料和问题；不接受访客指定系统提示、模型、接口地址或站方Key。结果须通过来源、引用和数字校验。网页不会自动上传持仓金额、笔记或收藏。

网页默认AI的额度与GitHub定时程序的额度分别记账：前者是人工使用的共享服务，后者是自动采集。模板各为5元/日，不能理解成两个运行环境自动共用一个5元台账。实际收费以服务商账单为准。

## 访客使用自己的AI

在网页“设置”中选择“自选 AI”，填写完整接口地址、自己的Key和模型名称，保存。填写内容只保存在该浏览器；请求直接发往所选服务商。切回默认AI后，请求不会携带已保存的自选Key。

自选AI同样使用产品提供的摘要、核对、问答提示，网页不提供改写系统提示的入口。服务商可能要求浏览器跨域支持；不支持时可使用默认AI服务。

## 多人访问与发布的边界

`WEB_LLM_ORIGIN`在本机使用时留空即可，`http://127.0.0.1:8765`、其他本机端口及`localhost`均由服务自动核对。这里填写的是网页的来源地址，不是模型API地址。以后部署时填“协议＋主机名＋非默认端口（如果有）”，例如`https://fund.example.com`或`https://fund.example.com:8443`；不要填写`/index.html`、`/api/ai`等路径，也不要在末尾加斜杠。设置后重启Node服务生效。Key继续只填在服务端。

当前网站发布仍关闭。本机127.0.0.1地址只有本机能访问。代码准备完成不等于已经上线共享服务。

以后需要让其他用户直接使用默认AI，应部署本包Node服务，并通过同一HTTPS域名提供网页和 `/api/ai`。在服务端填写 `WEB_LLM_ORIGIN` 为该HTTPS站点的完整origin（例如 `https://your-domain.example`，不带路径或末尾斜杠），Key仍保存在服务端环境中。当前此项留空，允许本机localhost使用。

GitHub Actions负责定时执行，不能当作持续运行的网页AI服务；GitHub Pages只托管静态文件，不能独立运行这个接口。本轮没有替用户注册托管服务、填Key或开启网站发布。
