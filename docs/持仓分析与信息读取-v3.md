# 持仓分析与信息读取 v3

更新：2026-11-25。依据同日《交接-持仓分析v3》《工作手册-持仓缺失与状态分级》及用户最新网页要求。新的页面组织替代v2，历史指标函数保留用于复核。

## 四个分析板块

| 板块 | 输入与规则 | 结果边界 |
|---|---|---|
| 持仓重叠 | 每对基金选最新共同详细报告期；完整报告或至少20行；占比不可缺失、合计不能明显超过净资产 | 比例为Σmin(pA,pB)。双边匹配金额为2Σmin(金额A×pA,金额B×pB)。等额5万元、重叠42.62%时为42,620元；金额不等时不能直接用总额乘重叠比例。多对不能相加。 |
| 风险与期限 | 优先已核总回报；另设来源日涨跌幅观察，至少200个共同有效交易日，最近三年，缺失日不拼接，货币基金排除 | 观察测算未经分红折算独立核验。保持来源日涨跌幅，不用单位净值比替代，不删除大涨跌后接起曲线。按当前金额折算历史回撤，并非个人收益或未来损失上限。 |
| 同指数费率 | 256个同指数组；只比较已取得的管理、托管项目 | 服务费缺失保持null。年费差额未含交易、申赎、折溢价和跟踪差异，不称为换仓净节省。 |
| 目标配置 | 用户明确保存目标，合计100%，覆盖全部当前基金；可清除 | 输入金额占比与目标之差为配置差。净值推算要求参考值及最新日期分别对齐，金额未改；假设份额不变，未处理期间分红折算申赎。 |

集中度、有效持股数等放到可展开说明。金额和目标留在当前浏览器，组合计算在网页完成，不上传每日程序。

`compute_daily_factors.py`发布各基金结构、已核风险资格及独立的`observedRisk/observedPressure`。正式`risk`不借观察数据升级为ready。网页的组合协方差、重叠与金额使用当前用户输入，因此不预存某一固定组合。

## 数据同步

`sync_analysis_v3.py`读取固定长度文件快照，跳过未写完整的最后一行，不改原文件。合并同代码同报告期更深明细，已核原报告优先；保留516160的110行中报。100行只是接口上限，不能标为完整持仓。六种状态、FOF持有基金、联接ETF参考与费率按需读取。

FOF来源未给报告日时保持null，抓取时间不代填。目标ETF权重不是联接基金自身股票权重，不计入直接穿透。债券类别的空股票表不等于法律上禁止持股。WB正在执行的top100与历史净值队列保持原状。

## 帖子和评论

东方财富裸ETF代码可能回退到全站`gssz`板块。现在核对返回的QCode和对象角色，拒绝错误板块，并过滤运营活动及其他基金、股票板块推荐。发布保留`boardVerified/nativeBoard`。旧材料未重新核对时标记关联待核。

新增新浪股市汇公开HTML解析，实际核对板块、帖子ID、原文正文、回复及分页。支持GB2312/GB18030和相对日期、月日格式，不保存用户名、账号或IP。来源拒绝访问时停止并冷却，不使用登录Cookie、验证码绕过或签名私有接口。

网页的“读取/继续读取帖子与评论”只接受已收录对象及近30天日期。服务端串行、限队列、每次100秒，保存列表页和评论位置；最多30帖/对象/日。已有缓存会在再次打开页面时显示。后台完整语料仍使用原有私有检查点；按需缓存位于`prototype/.private/forum`，不进入公开代码包。来源重复评论页保持partial，不写成零评论。

全目录建档、已排队、已取得列表、正文齐全、评论齐全是不同状态。部分板块没有昨日帖子，部分返回受限，热门板块需多次翻页。当前没有达到“所有对象昨日帖子和全部评论完整”的验收条件，不作此承诺。

## AI与界面

时间轴、公共资料库、帖子评论、我的资料库顶部都有AI分析，提供摘要、持仓关联、要点与分歧及自写问题。公共资料可辅助查询已收录对象；返回引用，缺原文只按已取得部分解释。原有固定系统约束仍生效，用户问题不替换系统提示。

时间轴标明相关基金、股票或市场。首页基金详情直接修改金额、删除。我的资料库仅发送勾选收藏的文字，图片不自动发送；持仓关联只提供基金资金比例和披露路径，默认不发送金额。材料按字节分配并标明节选，防止长正文挤掉全部评论。

本机`WEB_LLM_ORIGIN`留空即可。另部署服务时填写网页的来源，例如`https://example.com`，不带路径。Key在服务端`.env.local`填写，不放GitHub公开文件。原有默认AI配置可继续使用；新增公开论坛不需要填写API。

网站发布开关保持关闭，未接入或发布Team Hub。
