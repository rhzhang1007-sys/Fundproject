# 持仓分析与定时更新 v7

本版接入两部分：组合穿透与风险结构、基金成本与同类表现。只读已接入的公开数据，以及 WB 已完成的净值记录；未增加分析采集源，不改动运行中的采集任务。之后接入 WB 新批次时仍需检查代码身份、报告期、日期、权重和异常，不以下载完成代替验收。

## 数据及计算

- 当前持仓明细优先使用网页已验收的 `data/v11/relationships`。不直接使用 WB 的 `分片/holdings`：2026-11-25 检查发现 5,563 个代码复用了完全相同的一组持仓。原因是 `build_holdings_shards.py` 的第二个循环沿用了最后一条记录的 `periods`。代码已修正，增加跨基金串数据回归检查；没有运行该脚本或改写 WB 原始、分片文件。
- v7 取消20条门槛；半年度、年度的非空明细可以计算已披露重叠。日期、条数或100行上限都不证明完整。同期重叠使用占净资产的原始比例，不归一化。双边匹配金额 `2Σmin(金额A×pA,金额B×pB)`。不同基金对的金额不得相加。
- 名义与有效持股在全部所持基金的同一期详细披露内计算。已展开比例至少50%，其内部归一化后，有效只数为 `1/Σp²`。证券代码不等于最终企业去重。
- 复权观察须 `quality=clean`、`crossCheck=agree`，没有 `filledFromNav` 或 `skipped`，至少200个连续有效日收益。涉及多基金时使用共同交易日期。美元、货币等不适用口径不混入。
- `crossCheck=agree` 只表示同一数据源不同净值口径差异未超过试验阈值2个百分点。累计净值比值不等于分红再投资总回报；相同来源不构成独立外部验证。分歧不自动证明错误，通过也不升级为已核总回报。这个筛查可能排除本来有效的分红基金。所有 `verifiedTotalReturn` 仍为 false。
- 收益区间固定截至分析日。若 WB 序列含今天的数据，截至昨日后复用已有原始净值的起止累计净值重新筛查，不用今天的数据证明昨天可用。无法对齐则待核。
- 资金占比与波动贡献使用样本协方差（n−1），保留负贡献。历史路径按期初当前权重投入、基金间不调仓。历史折算金额不表示个人账户实际盈亏。
- 同类为基金类型全串＋规模档。R²采用250个共同日收益、至少30个其他同类，等权均值剔除本基金。它不是合同基准R²，也不能据此判定伪主动。被动基金只展示相似度。
- 费率优先同指数、同类型、同产品形式，再用同类型规模组。缺失销售服务费不填0，必要时只比较管理及托管两项。年费差额不含交易费用、折溢价、跟踪差异和生效条件，不表示换仓净节省。
- 六因子使用试验权重：成本25%、下行25%、正收益日20%、排名稳定15%、规模10%、持仓变化5%。每项至少30个同口径样本；至少3项且含下行或正收益日才出总分。成本因子整组使用同一费用项目。缺项按有效权重归一；总分分位仅比较相同因子组合且至少30个样本。规模倒U偏好不是有效性结论。
- 下行、正收益日采用同一250日区间；近1/2/3年排名稳定使用同组同日。年度明细权重余弦距离不等于交易换手。经理数为同管理人下同名经理关联的代码记录，包含多份额及历史，不推断精力。经理公告仅指已收录窗口，不能从30天材料推断90天无变更。
- 事后移除最差20日只做敏感性展示，不是可执行策略；现金分红和再投资收益的高低取决于后续表现，不预设现金收益更低。

`prototype/build-analysis-view.mjs` 没有网络请求。只读取 WB 稳定快照和已接入网页的公开资料，生成 `data/v14`。数据版本包含方法代码及输入文件哈希。日常只读取现有公开分片，使用已采到的逐日增长率延长序列；缺少交易日不补造。浏览器按持有代码读取对应分片，远端更新版本须与全部分片一致，失败整组回退本地版本，不能拼接两个版本。

## AI 解读与共享访问

预设“组合概览、重叠与分散、费用与同类、历史体验、数据限制”，另有自写追问。提示词保存在 `dist/v14-prompts.mjs`，网页自选 AI 和服务端默认 AI 共用。AI 只解释确定性计算结果，不代算因子或给交易建议。数字、材料 ID 和引用均由程序校验。用户可以查看每点依据并收藏结果。

默认不发送持有金额；基金代码、比例、统计指标及公开资料会送往选定模型。金额折算留在浏览器。组合信息和各人的收藏仍保存在自己的浏览器。

预设提示词随网页代码提供，所以从别处打开同一网页仍有同样按钮。访客直接使用站方默认 AI 还需要可访问的 Node 后端，通过同一个 HTTPS 域名提供网页和 `/api/ai`。本机 `127.0.0.1` 无法被其他人访问。GitHub Actions、纯静态 GitHub Pages 无法代替持续运行的服务。

新服务的填写步骤见[默认AI与自选AI配置](默认AI与自选AI配置.md)：服务端填 `WEB_LLM_API_URL`、`WEB_LLM_API_KEY`、`WEB_LLM_MODEL`；`WEB_LLM_ORIGIN` 填网页的协议和域名，不填模型地址和路径。本机留空。Key不进入公开代码，网站发布仍关闭。

`daily-runtime.mjs` 区分“当天有成功来源执行”与“数据覆盖完整”。备份触发读取当天执行记录，成功后不重复采集；失败保留重试机会。工作流按各自互斥组排队。新闻失败仍保存已验证的部分来源和状态，不把部分成功宣称全覆盖。

GitHub Actions 的 schedule 在默认分支运行，平台可能延迟或丢弃繁忙时段排队任务；补跑降低漏跑概率，不能保证准点或平台绝不漏触发。上线验收须分别确认工作流 active、远端 cron、实际运行和数据更新时间。发布工作流仍受关闭开关控制。
